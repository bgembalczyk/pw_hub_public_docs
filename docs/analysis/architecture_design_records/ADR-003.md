# ADR-003: Definition of Product Success Metrics (KPI)

## Status
ACCEPTED

## Context
The project lacked clearly defined success metrics (KPIs) in its Value Proposition Canvas and MVP definitions.
Previous documents listed "lack of metrics" as an assumption.
To validate the product value and prioritize features, we need measurable, specific indicators that can be tracked without full SSO implementation (as SSO is deferred).

## Decision
We define the following Key Performance Indicators (KPIs) for the MVP phase.
These metrics focus on user activity, event participation, and content consumption, measurable via device identifiers or session tracking.

### 1. Weekly Active Devices (WAD)
- **Definition:** Number of unique devices/installations opening the app at least once in a 7-day period.
- **Unit:** Unique Devices
- **Horizon:** Weekly
- **Success Threshold:** > 500 (pilot phase)
- **Goal:** Validate general interest and adoption.

### 2. Event Signup Conversion Rate
- **Definition:** Percentage of unique users (devices) who view an event details page and perform a "Sign Up" action (even if utilizing local storage or simplified flow in MVP).
- **Unit:** Percentage (%)
- **Horizon:** Monthly
- **Success Threshold:** > 5%
- **Goal:** Validate the core value proposition of "finding and attending events".

### 3. Active Unit Rate (Content Supply)
- **Definition:** Percentage of onboarded organizational units that publish at least one event or news item in a month.
- **Unit:** Percentage (%)
- **Horizon:** Monthly
- **Success Threshold:** > 80%
- **Goal:** Ensure the platform has fresh content to attract students.

### 4. 30-Day Retention
- **Definition:** Percentage of devices that open the app 30 days after the first launch.
- **Unit:** Percentage (%)
- **Horizon:** 30 days (rolling)
- **Success Threshold:** > 15%
- **Goal:** Validate long-term value and "stickiness" beyond novelty.

### 5. Average Content Interaction
- **Definition:** Average number of content items (news, event details) viewed per active user per session.
- **Unit:** Views per Session
- **Horizon:** Weekly
- **Success Threshold:** > 3 views
- **Goal:** Measure engagement depth.

## Consequences
### Positive
- **Measurability:** We can now objectively evaluate if the MVP is successful.
- **Focus:** Development and design can prioritize features that drive these specific metrics.
- **Validation:** Removes the "assumption" that we don't know how to measure success.

### Negative
- **Telemetry Requirement:** Requires implementing analytics (e.g., Firebase, PostHog) to track device-based events, which is an engineering task (though outside the scope of this ADR).
- **Proxy Metrics:** Without SSO, "Devices" is a proxy for "Students". We accept this inaccuracy for MVP.

## Compliance
- **VPC:** Updated to reference these KPIs.
- **MVP/MMF:** Aligned with these definitions.
- **JTBD:** Outcomes mapped to these metrics.
