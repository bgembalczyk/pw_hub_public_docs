# ADR-005: Alignment of Value Proposition Canvas with MVP Scope

## Context
The Value Proposition Canvas (VPC) described features like Campus Maps and USOS Integration as active value drivers. However, these features are explicitly deferred in `deferred_tasks.md`. This caused confusion about the actual MVP scope.

## Decision
We decided to strictly label non-MVP features in the VPC and other high-level documents.
- VPC is a "Vision" document but must clearly distinguish MVP vs Post-MVP.
- Features deferred to MMF (like Maps and USOS) must be tagged as `[POST-MVP]` in the VPC.
- `deferred_tasks.md` is the Single Source of Truth for deferred items.
- `moscow.md` and `specs.md` must reflect this deferral (WON'T HAVE or Status: Deferred).

## Consequences
- Reduces risk of scope creep.
- Clarifies expectations for stakeholders.
- VPC remains a valid "Vision" artifact without misrepresenting the current delivery scope.
